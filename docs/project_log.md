## หลักการที่ใช้กับทุกเว็บ (L4 Web Scraping)

ทุกเว็บใช้ขั้นตอนเดียวกัน 5 ขั้น:

1. **อ่าน robots.txt ก่อน** เพื่อดูว่าเว็บอนุญาตให้ดึงหน้าไหน
2. **สำรวจโครงสร้างหน้าด้วยมือ** ดูว่าข้อมูลอยู่ใน HTML tag ไหน และทำอย่างไรจึงจะย้อนไปดูสัปดาห์เก่าได้
3. **เขียนสคริปต์ที่มีโหมด `--test`** ดึงแค่ไม่กี่หน้าแล้วพิมพ์ผล ยังไม่บันทึก เพื่อเช็คก่อนรันจริง
4. **รันจริงแบบสุภาพ** คือหน่วงเวลา 1.5 วินาทีระหว่าง request ลองใหม่ได้สูงสุด 3 ครั้งถ้า error และแสดง progress ตลอด
5. **ตรวจคุณภาพไฟล์ที่ได้** ได้แก่ จำนวนแถว ค่าว่าง ข้อความซ้ำ ขยะ HTML และวันที่

รูปแบบข้อมูล (schema) ของทุกไฟล์: `source, week, zodiac, text`
- `week` = วันเริ่มสัปดาห์ (YYYY-MM-DD, ค.ศ.) โดยแปลง พ.ศ. เป็น ค.ศ. เช่น 2569 → 2026
- `zodiac` = ชื่อราศีภาษาอังกฤษ
- `text` = คำทำนายทั้งหมดของราศีนั้น (ส่วนการงาน การเงิน ความรัก ฯลฯ รวมเป็นข้อความเดียว)

**กฎเรื่องไฟล์ดิบ:** ห้ามเขียนทับไฟล์ใน `data/raw/` ถ้ามีไฟล์อยู่แล้ว สคริปต์จะบันทึกเป็นชื่อใหม่ `<site>_<วันเวลา>.csv` เอง

โค้ดที่ทุกสคริปต์ใช้ร่วมกัน: ฟังก์ชันดาวน์โหลดที่หน่วงเวลาและลองใหม่ได้

```python
HEADERS = {"User-Agent": "Mozilla/5.0 ... Chrome/130.0 Safari/537.36",
           "Accept": "text/html,...", "Accept-Language": "th,en;q=0.8"}
DELAY = 1.5  # seconds between requests (be polite)

def get(url):
    for attempt in range(3):              # up to 3 tries
        try:
            r = requests.get(url, headers=HEADERS, timeout=30)
            r.raise_for_status()
            time.sleep(DELAY)
            return r.text
        except requests.RequestException:
            time.sleep(5)                 # wait, then retry
    return ""
```

**เหตุผลที่ต้องใส่ header แบบเบราว์เซอร์:** marumura ตอบ `406 Not Acceptable` ถ้าเราไม่บอกว่าเป็นเบราว์เซอร์

### โค้ดหลัก
อ่านชื่อโพสต์ด้วย **regex (L2)**:
```python
TITLE_RE = re.compile(
    r"ดวงรายสัปดาห์\s*ราศี(?P<sign>\S+)\s+"
    r"(?P<d1>\d{1,2})\s*(?P<m1>[ก-๙]+)?\s*[–-]\s*"     # start day (+ month if the week crosses months)
    r"(?P<d2>\d{1,2})\s*(?P<m2>[ก-๙]+)\s*(?P<year>\d{4})"
)
```
ดึงข้อความด้วย **BeautifulSoup (L4)**:
```python
for el in block.find_all(["p", "h4"]):
    if el.name == "h4":      # "เรื่องแนะนำ" = end of the prediction
        break
    parts.append(el.get_text(" ", strip=True))
```

### การตัดสินใจและเหตุผล
- **ไม่ใช้ปีจากชื่อโพสต์ แต่ใช้วันที่โพสต์แทน:** ชื่อโพสต์ที่ข้ามปีเขียนแบบ "29 ธันวาคม – 4 มกราคม **2568**"
  ปีในชื่อจึงเป็นปีของวันเริ่ม ไม่ใช่วันจบ ซึ่งชวนสับสน สคริปต์จึงเลือกปีที่ทำให้วันเริ่มสัปดาห์ใกล้วันโพสต์ที่สุด
  ```python
  candidates = [date(published.year + dy, month, day) for dy in (-1, 0, 1)]
  return min(candidates, key=lambda d: abs((d - published).days))
  ```
- **ไม่เอา `<blockquote>` ด้านบนโพสต์** เพราะเป็นข้อความซ้ำกับย่อหน้าแรก
- **หยุดเปิดหน้ารายการเมื่อเจอสัปดาห์ที่ 27** ใช้ 17 หน้า แทนที่จะเปิดทั้ง 273 หน้า

### ปัญหาที่เจอและวิธีแก้
| ปัญหา | วิธีแก้ |
|---|---|
| `406 Not Acceptable` | ใส่ header แบบเบราว์เซอร์ |
| `SSLError` เป็นระยะ (เว็บตัดการเชื่อมต่อ) | เพิ่มให้ลองใหม่ได้ 3 ครั้ง และรอ 5 วินาทีก่อนลองใหม่ ทุกโพสต์ดึงได้ครบ |

### ผลลัพธ์
**312 แถว = 26 สัปดาห์ × 12 ราศี ครบ** (2026-05-18 ถึง 2026-11-09)
ยาว 290–935 ตัวอักษร (เฉลี่ย 527) ไม่มีขยะ HTML หรือลิงก์หลุดมา ใช้เวลารันประมาณ 12 นาที

### 🔍 สิ่งที่พบ: marumura เอาคำทำนายเก่ามาใช้ซ้ำ (ใช้ในรายงานได้)
วัดความคล้ายของข้อความทุกคู่ด้วย **TF-IDF + cosine similarity (L6, L9)**:
```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
X = TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 5)).fit_transform(df.text)
S = cosine_similarity(X)          # 312 x 312 matrix
np.fill_diagonal(S, 0)
i, j = np.where(np.triu(S) > 0.7) # pairs that are almost the same text
```
(ใช้ character n-gram เพราะไม่ต้องตัดคำ จึงเร็วและเหมาะกับการหาข้อความซ้ำ)

**ผล:** พบ **32 คู่ที่เกือบเหมือนกัน** (> 0.7) ในนี้ **19 คู่เป็นคนละราศีกัน**
- สัปดาห์ 19 ต.ค. เกือบทั้งสัปดาห์เป็นข้อความชุดเดียวกับสัปดาห์ 13 ก.ค. แต่สลับราศี
  เช่น ราศีสิงห์ (19 ต.ค.) คล้ายกับราศีมีน (13 ก.ค.) ถึง **0.97** และราศีพฤษภ (19 ต.ค.) คล้ายกับราศีตุลย์ (13 ก.ค.) ถึง **0.97**

**ความหมาย:** เป็นหลักฐานโดยตรงของ **Barnum effect** เพราะข้อความเดียวกันถูกใช้กับคนละราศีได้

### ทำไมต้องใช้ Selenium (L4)
requests ได้แค่ HTML ตอนเปิดหน้าครั้งแรก ซึ่งมี id แค่ 4 สัปดาห์ id ของสัปดาห์ที่เก่ากว่านั้นจะมาก็ต่อเมื่อ**กดปุ่ม "ดูเพิ่ม"**

```python
driver = webdriver.Chrome(options=options)          # options: --headless=new
driver.get(f"{BASE}/archive")
for click in range(1, MAX_CLICKS + 1):
    buttons = [b for b in driver.find_elements(By.TAG_NAME, "button") if "ดูเพิ่ม" in b.text]
    driver.execute_script("arguments[0].click();", buttons[0])
    time.sleep(2.5)                                   # wait for new weeks to load
    ids = ID_RE.findall(driver.page_source)           # +5 weeks per click
```

### กฎการทำความสะอาด (ตรงกับข้อ 1–5 ที่ทีมเห็นชอบ)

**sanook แบบ strict ตัด "คำแนะนำ":** คำนี้ยังโผล่ในเนื้อหาด้วย เช่น "ทำตามคำแนะนำอย่างมีเหตุผล" (58 แถวมีคำนี้มากกว่า 1 ครั้ง)

```python
ADVICE_RE = re.compile(r"(?<=\s)คำแนะนำ(?=\s)")     # stand-alone word only (L2 lookbehind/lookahead)
m = ADVICE_RE.search(text, text.find(" สุขภาพ "))
```

แต่ไม่ตัดภาษาอังกฤษทั้งหมด เพราะมีคำว่า "AI" ที่เป็นเนื้อหาจริงอยู่
```python
_RANKS = "Ace|Two|Three|...|Page|Knight|Queen|King"
_SUITS = "Cups|Pentacles|Swords?|Wands?"
_MAJOR = "Wheel of Fortune|The Hanged Man|The High Priestess|The [A-Z][a-z]+|Death|Judgement|Justice|Strength|Temperance"
CARD_RE = re.compile(rf"(?<![A-Za-z])(?:(?:The )?(?:{_RANKS}) of (?:{_SUITS})|{_MAJOR})(?![A-Za-z])(?:\s*\(กลับหัว\))?")
```

### ทำอะไร (L6 TF-IDF, L9 cosine similarity)

1. **ระดับเอกสารรวม (ตามแผนใน CLAUDE.md):** รวมทุกข้อความของราศีเดียวกันเป็น 1 เอกสาร → TF-IDF → cosine → heatmap 12×12
   และทำแบบเดียวกันกับ 4 เว็บ (heatmap 4×4) โดยใช้สเกลสีเดียวกัน (0–1) จึงเทียบกันด้วยตาได้
2. **ระดับข้อความเดี่ยว (เพิ่มเอง):** TF-IDF ของข้อความทั้ง 1,233 ข้อความ → cosine ของทุกคู่ (≈ 760,000 คู่)

   + **permutation test** ภายในแต่ละเว็บ (สลับป้ายราศี 1,000 ครั้ง)

```python
# TF-IDF on texts that are already tokenized: analyzer=identity so sklearn does not split them again
X = TfidfVectorizer(analyzer=identity, min_df=2).fit_transform(df["tokens"])
S = cosine_similarity(X)                       # 1,233 x 1,233
i, j = np.triu_indices(len(df), 1)             # every pair once
# permutation test: d = mean(same-sign pairs) - mean(different-sign pairs), shuffle sign labels 1,000 times
p = (1 + (null >= observed).sum()) / (n_perm + 1)
```

| ทายราศีของ sanook ได้ 99% แม้ตัดย่อหน้าแรกแล้ว | โมเดลใช้คำว่า "ราศีมกร" และ "ราศีมิถุน" ซึ่งเป็นชื่อราศีที่สะกดอีกแบบ และ `clean_text` ไม่รู้จัก | ทีมอนุญาตให้เพิ่ม "มิถุน", "มกร", "สันย์" (คำที่ sanook พิมพ์ผิดจาก กันย์) ใน `EXTRA_SIGN_SPELLINGS` แล้วรัน 01 และ 02 ใหม่ (ตัวเลขเปลี่ยนแค่หลักทศนิยมที่ 2–3) |
| แก้ชื่อราศีแล้ว sanook ยังทายได้ 70% ด้วย `text_strict` | ดูคำที่มีน้ำหนักสูงในโมเดล พบคำเรื่องสุขภาพ เช่น ราศีเมษ "ปวดศีรษะ ไมเกรน" ส่วน "สุขภาพ" จึงเป็นย่อหน้าที่ใช้ซ้ำด้วย | เพิ่มส่วนที่ 6: ทายราศีจาก**ทีละส่วน**ของ sanook |

### ผลลัพธ์หลัก
| งาน | chance | accuracy (5-fold CV, โมเดลที่ดีที่สุด) | p เทียบกับ chance |
|---|---|---|---|
| ทายเว็บ | 25% | **100%** | < 0.001 |
| ทายราศี ทุกเว็บรวม | 8.3% | 31.4% (เกือบทั้งหมดมาจาก sanook) | < 0.001 |
| ทายราศี marumura | 8.3% | **7.1%** | 0.82 |
| ทายราศี thairath | 8.3% | **11.7%** | 0.03 (อ่อนมาก, อีก 2 โมเดลได้ 10.3%) |
| ทายราศี kapook | 8.3% | **10.6%** | 0.09 |
| ทายราศี sanook | 8.3% | 99.4% → 65.7% (`text_strict`) | < 0.001 |

sanook แยกทีละส่วน: **คำแนะนำ 99%, สุขภาพ 75%** (ไม่ซ้ำแค่ 14/26 สัปดาห์ต่อราศี) ส่วน การเงิน 16%, การงาน 10%, ความรัก 28% (เขียนใหม่ทุกสัปดาห์)

คำที่ใช้แยกเว็บ (Logistic Regression) คือสไตล์ภาษา: marumura "อย่า/เอาเป็นว่า/เดี๋ยว", sanook "ดาว/เขต/โคจร/สถิต",
thairath "คู่/เกณฑ์/ขอให้", kapook "สถานการณ์/เรื่องสำคัญ/คำเตือน"

**ข้อสรุป:** ทายเว็บได้สมบูรณ์ แต่ทายราศีได้แค่ระดับเดาใน 3 จาก 4 เว็บ ซึ่งเข้าเงื่อนไข **Barnum effect** ที่ตั้งไว้
sanook ทายได้เพราะ**ย่อหน้าประจำราศีที่ใช้ซ้ำ** (คำแนะนำ, สุขภาพ) ไม่ใช่เพราะคำทำนายรายสัปดาห์ต่างกัน

### บทเรียนสำหรับรายงาน
- **ตัวเลขรวมหลอกตาได้:** ทายราศีแบบรวมทุกเว็บได้ 31% ดูเหมือนราศีต่างกัน แต่เมื่อแยกตามเว็บจะเห็นว่ามาจาก sanook เว็บเดียว
- **ต้องดูว่าโมเดลใช้คำอะไร** (feature weights) จึงจะเจอปัญหาอย่างชื่อราศีที่หลุดมา และย่อหน้าที่ใช้ซ้ำ
- **การเลือกโมเดลที่ดีที่สุดจากหลายโมเดลทำให้ p ดูดีเกินจริง** จึงต้องตีความ p = 0.03 ของ thairath อย่างระวัง

### การตัดสินใจและเหตุผล (ทีมเห็นชอบให้ทำ A + B)
- **ทำไมเพิ่มส่วน B:** ตอนทดลองพบว่า LDA บนทุกข้อความได้ topic ที่ตรงกับเว็บ แม้จะลองเก็บแค่ "คำที่ใช้ร่วมกัน ≥ 3 เว็บ" (181 คำ) ก็ยังได้ topic ที่ประมาณ 80% มาจากเว็บเดียว
  แปลว่าแม้แต่คำทั่วไปแต่ละเว็บก็ใช้ในสัดส่วนต่างกัน จึงต้องทำ topic model ภายในเว็บเดียวกัน (เหมือนที่ 02/03 เทียบภายในเว็บ)
- **ไม่เลือก k = 2** แม้ coherence ของ LDA จะสูงสุดเล็กน้อยที่ k = 2 (0.488 กับ 0.484 ที่ k = 3) เพราะ 2 topic หยาบเกินไปที่จะตั้งชื่อหัวข้อ

|---|---|
| ตามเว็บ | thairath **+0.10** (บวก 54%) > marumura +0.04 (กระจายมาก) > kapook +0.003 > sanook −0.02 (กลาง 91%) |
| ตามราศี (ทุกเว็บรวม) | ราศีธนูสูงสุด +0.052 และราศีสิงห์ต่ำสุด +0.017 แต่ **p = 0.20** ช่วงความเชื่อมั่นซ้อนกันทั้งหมด |
| eta² | **เว็บอธิบายได้ 12.4% และราศีอธิบายได้ 0.7%** |
| ภายในเว็บ | marumura p = 0.93; thairath p = 0.04 (ไม่ผ่าน Bonferroni); kapook p = 0.011 (ผ่านแบบหวุดหวิด แต่ eta² = 0.07 ใกล้ค่าที่ได้โดยบังเอิญ ≈ 0.035); sanook p < 0.001 (ย่อหน้าประจำราศี) |

**ข้อสรุป:** น้ำเสียงของดวงขึ้นกับ**เว็บ** ไม่ใช่**ราศี** ซึ่งเป็นหลักฐานชิ้นที่ 5

### บทเรียนสำหรับรายงานและ presentation
- **โมเดลสำเร็จรูปอาจใช้กับข้อความต่างโดเมนไม่ได้** ต้องตรวจกับข้อมูลจริงก่อนเชื่อ ถ้าไม่ตรวจ เราจะรายงานว่า "ดวงเกือบทั้งหมดเป็นกลาง" ซึ่งผิด
- **ทดสอบหลายครั้ง (4 เว็บ) ต้องปรับเกณฑ์ p (Bonferroni)** และดู effect size ด้วย ไม่ใช่ดูแค่ p < 0.05
- **ข้อเสนอ:** ให้สมาชิก 2 คนติดป้ายชุดตรวจสอบแยกกัน แล้ววัดความตรงกันระหว่างคน (inter-annotator agreement)

## ขั้นที่ 13: 06_clustering (stretch goal) (2026-11-15)

`06_elbow_silhouette.png` (รูปที่ 16), `06_crosstab_clusters.png` (รูปที่ 17), `06_pca_site_vs_sign.png` (รูปที่ 18)

### ทำอะไร (L9 Clustering)
- TF-IDF ของคำ (`min_df=2`, 3,848 คำ) → **K-means** (`n_init=10`) ลอง k = 2–15
- เลือก k ด้วย **elbow (WCSS)** และ **silhouette (cosine)** แล้วลอง **k = 4** (= จำนวนเว็บ) และ **k = 12** (= จำนวนราศี) ตามแผน
- วัดด้วย **ARI** เทียบกับเว็บและกับราศี ทั้งแบบทุกข้อความและแบบภายในแต่ละเว็บ
- **PCA** 2 มิติ (ใช้ `X.toarray()` เพราะ PCA ต้องใช้เมทริกซ์ปกติ ข้อมูลไม่ใหญ่จึงทำได้)

### การตัดสินใจเรื่องกราฟ
แผนเดิมคือ "PCA scatter 2 รูปคู่กัน ระบายสีตามราศีและตามเว็บ" แต่ **12 สีในกราฟเดียวแยกด้วยตาไม่ได้**
และแม้แต่ 4 สีของเว็บ ใน scatter ที่จุดทุกสีอยู่ติดกันได้ validator ยืนยันว่าแยกได้ชัดแค่ 3 สี
จึงเปลี่ยนเป็น **small multiples**: แผงเล็กหนึ่งแผงต่อหนึ่งเว็บ (4) และต่อหนึ่งราศี (12) เน้นจุดของกลุ่มนั้นทับบนจุดสีเทาของทั้งหมด

### ผลลัพธ์หลัก
| สิ่งที่วัด | ผล |
|---|---|
| k ที่ silhouette สูงสุด | **k = 4** (0.094) แล้วตกเหลือ 0.044 ที่ k = 5 |
| k = 4 กับเว็บ | **ARI = 0.998** (ผิดแค่ 1 ข้อความจาก 1,233) |
| k = 12 กับราศี | ARI = 0.028 และ**ทุกกลุ่มมาจากเว็บเดียว**; กลุ่มที่ตรงกับราศี 4 กลุ่มมาจาก sanook ทั้งหมด |
| k = 12 ภายในเว็บ กับราศี | marumura 0.008, thairath 0.003, kapook 0.006, sanook 0.67 |
| PCA | เว็บเป็นก้อนแยกกัน 4 ก้อน แต่ทุกราศีกระจายอยู่ในทั้ง 4 ก้อน |

**ข้อสรุป:** โมเดลที่ไม่รู้ป้ายเลยเลือกเองว่ามี **4 กลุ่ม = 4 เว็บ** ไม่ใช่ 12 กลุ่ม = 12 ราศี ซึ่งเป็นหลักฐานชิ้นที่ 6

## ขั้นที่ 14: 07_summarization (stretch goal) (2026-11-15)

ไฟล์: [notebooks/07_summarization.ipynb](../notebooks/07_summarization.ipynb) → `07_rouge_heatmap.png` (รูปที่ 19)

### ทำอะไร (L8 Summarization, extractive)
- **ตัดประโยค:** ภาษาไทยไม่มีจุด จึงรวมวลีที่เว้นวรรคจนยาว 60–200 ตัวอักษร (4,577 "ประโยค" จาก 1,177 ข้อความ)
  ใช้ `text_strict` และตัด `near_duplicate` ออก เพื่อให้สรุปมาจากคำทำนาย ไม่ใช่ย่อหน้าที่ใช้ซ้ำ
- **3 วิธี:**
  - Lead-3 = ประโยคแรกของคำทำนาย 3 อันล่าสุด
  - TextRank = PageRank บนกราฟ cosine ของ TF-IDF
  - LexRank = PageRank บนกราฟที่เก็บเฉพาะเส้นที่ cosine ≥ 0.1
  - ทั้งสามวิธีข้ามประโยคที่คล้ายประโยคที่เลือกแล้วเกิน 0.5
- **ROUGE-1/2 F1 คำนวณเอง** จากคำที่ตัดด้วย PyThaiNLP (แพ็กเกจ `rouge-score` ตัดคำไทยไม่ได้) **จึงไม่ต้องติดตั้งอะไรเพิ่ม** (networkx มากับ torch แล้ว)

```python
graph = nx.from_numpy_array(cosine_similarity(X))         # TextRank: edge weight = cosine
scores = nx.pagerank(graph, weight="weight")              # most "central" sentences = best summary
overlap = sum((ngrams(a, n) & ngrams(b, n)).values())     # ROUGE-N: matching n-grams
```

| **L2 Regex** | อ่านราศีและวันที่จากชื่อบทความ, แยกข้อความ kapook ตามหัวข้อราศี, หา id ของ thairath, ตัดชื่อไพ่ (lookbehind/lookahead แทน `\b` สำหรับภาษาไทย), หาหัวข้อ "คำแนะนำ" |
| **L4 Web Scraping** | robots.txt, requests + header, BeautifulSoup (CSS selector, `find_all`), pagination, **Selenium** กดปุ่มที่ใช้ JavaScript, อ่าน JSON API/`__NEXT_DATA__`, หน่วงเวลา, retry |
| **L5 Data Preparation** | `src/thai_text.py`: normalize, ลบชื่อราศี (แก้ให้ลบเฉพาะคำเต็มคำหลังตัดคำ), ตัดคำ newmm + พจนานุกรมคำโหราศาสตร์, ตัด stopword; `src/build_dataset.py`: รวมไฟล์, จับคู่สัปดาห์, ตัดข้อความที่บอกราศีโดยตรง |
| **L3 Visualization** | 01_eda: histogram, boxplot, bar chart คำที่พบบ่อย, word cloud 12 ราศี (ฟอนต์ไทย + แก้การวางสระ), สีที่คนตาบอดสีแยกได้ |
| **L6 Feature Representation** | TF-IDF (character n-gram) สำหรับหาข้อความซ้ำ และติด flag `near_duplicate`; 02: TF-IDF ของคำ (หลังตัดคำ) ทั้งระดับเอกสารรวมและข้อความเดี่ยว |
| **L7 Classification** | 03: Naive Bayes / Logistic Regression / SVM, 80:20 stratified + 5-fold CV, precision/recall/F1, confusion matrix, เทียบกับระดับเดา, กันข้อมูลรั่วด้วย `StratifiedGroupKFold` |
| **L10 Topic modeling** | 04: LSA vs LDA (gensim), เลือก k ด้วย c_v coherence, top words, สัดส่วน topic ตามเว็บและตามราศี; BERTopic (embedding → UMAP → HDBSCAN → c-TF-IDF) + ARI |
| **Pre-trained sentiment (ส่วนเสริมที่อนุญาต)** | 05: WangchanBERTa sentiment จาก Hugging Face, ตรวจกับชุดที่คนติดป้าย (AUC, Spearman, leave-one-out), Kruskal-Wallis + Bonferroni, eta² |
| **L8 Summarization** | 07: Lead-3, TextRank, LexRank (networkx PageRank), ROUGE-1/2 ที่คำนวณเองสำหรับภาษาไทย, universal horoscope |
| **L9 Clustering (distance)** | cosine similarity วัดความคล้ายของข้อความทุกคู่; 02: heatmap 12×12 / 4×4, เทียบความคล้ายภายในกลุ่มกับข้ามกลุ่ม + permutation test; 06: K-means, elbow (WCSS), silhouette, ARI, PCA |
